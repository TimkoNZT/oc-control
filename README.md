# oc-control

MCP-сервер для OpenCode V2, дающий расширенные возможности управления проектами и сессиями, наблюдение за субагентами и сообщения между сессиями. Один файл, чистый JavaScript, без сборки и зависимостей. Подключается к фоновому сервису OpenCode через `service.json` — адрес и пароль настраивать не нужно.

## Требования

- Node.js 22.13+ (нужен встроенный `node:sqlite`).
- Запущенный OpenCode V2.

## Установка

`opencode.json`:

```json
{
  "mcp": {
    "oc-control": {
      "type": "local",
      "command": ["node", "<путь к oc-control.mjs>"],
      "enabled": true
    }
  }
}
```

## Подключение к сервису

OpenCode V2 запускает общий фоновый сервис на localhost с Basic auth. При старте он
пишет `service.json`:

```json
{ "url": "http://127.0.0.1:<port>", "pid": 1234, "password": "..." }
```

Сервер читает оттуда адрес и пароль, поэтому в конфиге MCP не нужны ни порт, ни токен.
Файл содержит пароль — не публикуйте его.

Основные места поиска (берётся первый файл с полем `url`):

1. `OC_SERVICE_FILE`, если задан;
2. `~/.local/state/opencode/service.json` — стандартное место;
3. `%LOCALAPPDATA%\opencode\service.json` — запасной вариант для Windows.

На Linux при заданном `XDG_STATE_HOME` он проверяется сразу после `OC_SERVICE_FILE`.
Если файла нет, сервер вернёт ошибку с подсказкой задать `OC_URL`. Полный обход файла —
`OC_URL` и при необходимости `OC_PASSWORD`.

| Переменная        | Назначение                                                             |
| ----------------- | ---------------------------------------------------------------------- |
| `OC_SERVICE_FILE` | явный путь к `service.json`                                            |
| `OC_URL`          | адрес сервиса без чтения файла                                         |
| `OC_PASSWORD`     | пароль Basic auth вместе с `OC_URL`                                    |
| `OC_DB`           | путь к `opencode.db` для операций с проектами (к сервису не относится) |

## Инструменты

`?` — необязательный аргумент, в скобках — значение по умолчанию. Лишние аргументы
и неверные типы отклоняются, числа и boolean приводятся к нужному виду.

### Сервис и история

| Инструмент    | Аргументы                                                             | Назначение                                                                                                                                                                                                                                                                                  |
| ------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `oc_health`   | —                                                                     | Проверяет сервис: `healthy`, `url`, `servicePid`, версия **сервиса** (версия самого MCP видна в `initialize`).                                                                                                                                                                              |
| `oc_sessions` | `limit` (30, max 1000), `rootsOnly` (true), `includeChildren` (false), `activeOnly` (false) | Список сессий, свежие сверху: `id`, `title`, `agent`, `model`, `parentID`, `busy`, `active`, `outcome`, `elapsedSec`, `tokens`. `elapsedSec` — возраст с создания, не время последней активности. `includeChildren` добавляет детей только занятым и только при `rootsOnly:true`. `activeOnly` оставляет только сессии с `active: true`; `context`: `limit`, `used`, `remaining`, `percent`, `stale`. |
| `oc_messages` | `sessionId`, `limit` (5, max 50), `order` (`desc`/`asc`)              | Последние сообщения: `type`, `at`, `text`, `model`, `tokens` (токены этого шага). Текст схлопнут и обрезан до 400 символов, вызовы инструментов помечены.                                                                                                                                     |
| `oc_prompt`   | `sessionId`, `text`, `from`, `delivery` (`steer`), `resume` (true)    | `steer` (по умолчанию) — вклиниться в текущий прогон; `queue` — на следующий ход. `from` добавляет `[from: ...]` первой строкой. `resume: false` только кладёт во входящие, не будит. API `prompt` умеет `files`, `agents`, `skills`, `metadata`, но инструмент пока передаёт только текст. |

### Проекты и сессии

| Инструмент          | Аргументы                                                                                                          | Назначение                                                                                                                                                                                                                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `oc_create_session` | `directory?`, `title?`, `parentID?`, `agent?`, `model?`                                                            | Создаёт корневую сессию в `directory` (по умолчанию — каталог вызывающей) или субагента при `parentID`. `directory` и `parentID` взаимоисключающие. `model` — строка `"providerID/modelID"` (например `"opencode-go/deepseek-v4.1-flash"`, можно `:variant`) или `{providerID, id, variant?}`. Без `model` берётся модель агента или по умолчанию. `title` обрезается до 200. |
| `oc_projects`       | `includeArchived` (false), `includeCounts` (true)                                                                  | Список проектов: `id`, `canonical`, `name`, `sandboxes`, `archived`, `archivedAt`, `sessions`, `activeAt`. `includeArchived` добавляет архивные (старое имя — `archived`); `sessions` считается по всем сессиям.                                                                                                                                      |
| `oc_project_edit`   | `projectId`, `canonical`, `name`, `icon`, `commands`, `archived`, `moveSessions` (true), `moveAllSessions` (false) | При смене `canonical` переносит сессии, обновляет `session_v2.path`, `project_directory` и `sandboxes`; для каталога без VCS пересчитывает `id`, внутри VCS — не трогает. `moveAllSessions` переносит и сессии вне старого корня. `archived` пишет напрямую в БД. Возвращает `before`/`after`, `via`, `sessionsMoved`, `sessionsSkipped`, `warnings`. |
| `oc_session_edit`   | `sessionId`, `title`, `directory`, `archived`, `permissions`, `metadata`                                           | `title` обрезается до 200, пустой отклоняется. `directory` вызывает API move, ждёт применения около 6 секунд и возвращает `notes`. `archived` меняется через API.                                                                                                                                                                                     |
| `oc_session_delete` | `sessionId`, `dryRun` (false)                                                                                      | Удаляет сессию и всех потомков через API, затем чистит `todo`, `job`, `event`, `event_sequence` и обнуляет `fork_session_id`. Необратимо; `dryRun` считает сессии и сообщения.                                                                                                                                                                        |
| `oc_project_delete` | `projectId`, `force` (false), `dryRun` (false)                                                                     | Каскадное удаление через БД. Без `force` откажется, если есть сессии. `dryRun` показывает сессии, сообщения, sandboxes, worktree и занятые сессии. `global` и проект вызывающей сессии защищены. Ошибки очистки возвращаются в `cleanupErrors`.                                                                                                       |

### Субагенты

| Инструмент    | Аргументы                                                                 | Назначение                                                                                                                                                                                                                                           |
| ------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `oc_report`   | `text`, `kind` (`progress`), `resume`, `to`                               | Отчёт родителю как synthetic. `progress` по умолчанию `resume: false` → во входящие; `result`/`blocked` → `resume: true`, будят и попадают в историю. Без `to` получатель — родитель вызывающей сессии.                                              |
| `oc_watch`    | `sessionId?`, `waitSec` (0), `pollSec` (5), `includeMessages` (3), `full` | Без `sessionId` — все дети вызывающей. `waitSec: 0` — снимок; иначе ждёт с двумя подряд холостыми опросами. `pollSec` 1–60, `waitSec` до 3600. `full` добавляет время/стоимость/токены только в режиме снимка. Ошибки дают `idle: false` и `errors`. В сессиях есть `active`, `context` (`limit`, `used`, `remaining`, `percent`). Лимита по количеству нет — ждёт всех детей. |
| `oc_children` | `sessionId?`, `limit` (30, max 1000), `includeMessages` (3), `activeOnly` (false) | Дети сессии (по умолчанию вызывающей): `parentID`, `count`, `total`, `limit`, `truncated`, `sessions`. `total` — после `activeOnly`, `count` — после `limit`, `truncated` — лимит отрезал часть. `activeOnly` оставляет только сессии с `active: true`. |
| `oc_inbox`    | `sessionId?`, `limit` (20, max 200)                                       | Доставленные, но не обработанные сообщения: `type`, `delivery`, `at`, `text` (до 300 символов), `metadata`.                                                                                                                                          |

## Тесты

```
node test.mjs
```

E2E-тест гоняет сервер через stdio. Нужен живой OpenCode V2 и хотя бы один субагент;
сессии и каталоги находятся автоматически, зашитых путей и ID нет.

По умолчанию тест не пишет в чужие сессии и не удаляет существующие сессии или проекты.
Полный набор переменных:

```
TEST_PARENT, TEST_CHILD   явные сессии вместо автопоиска
TEST_CHILD_TARGET         одноразовая сессия для проверки сообщений
TEST_PROJECT              id проекта для проверки архивации
TEST_MOVE_DIR             каталог для проверки переноса
TEST_DELETE_SESSION       сессия, которую разрешено удалить
TEST_DELETE_PROJECT       проект, который разрешено удалить
```

Тест не read-only: временно переименовывает и переносит дочернюю сессию, создаёт и удаляет
временную сессию, архивирует и разархивирует проект — затем всё восстанавливает.
